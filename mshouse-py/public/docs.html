1. 概述

MSHouse 是一套纯软件运行的虚拟智能家居，用数字孪生的方式还原一栋两层别墅： 客厅、厨房、主卧、卫生间、门厅五个房间，灯、空调、温湿度传感器、云台摄像头、人脸门锁五类设备。 所有设备都有真实的状态、响应与联动逻辑，不依赖任何实体硬件，适合课堂教学、协议演示与二次开发。

系统分为两层：

  • 网关（server）：FastAPI + asyncio，维护设备影子、执行场景、广播状态、提供 MJPEG 画面流。
  • 呈现（public）：Three.js 三维沙盘 + 控制面板，与网关通过 WebSocket 通信。

核心设计是协议与呈现分离：只要理解 WebSocket/MQTT 报文，就能用任意语言或平台控制这栋房子。

3. 工作流程

3.1 启动

  1. 安装依赖：pip install -r requirements.txt
  2. 启动网关：python -m server.main（默认 http://localhost:8080）
  3. 浏览器打开首页，WebSocket 自动连接并拉取全量设备影子。

3.2 首次使用

点击顶部「设置」按钮，输入口令 villa 后可写入住宅位置（经纬度、地点名）。 写入后网关会按当地天气预报初始化室外温湿度，并影响室内传感器与空调的初始值。 你也可以在设置里把大门锁画面来源切换为：静态画面（默认，按天气切换）、本机摄像头、网络视频流（RTSP / HTTP-MJPEG）。

3.3 日常交互

  • 三维视图：拖拽旋转、滚轮缩放、点击设备查看高亮。房子前方显示当前地点名称。
  • 控制面板：右侧「控制」标签分页列出所有设备卡片，可直接开关、调光、调温、转动云台、上锁/开锁。
  • 场景按钮：顶栏「回家 / 离家 / 睡眠 / 观影」一键批量切换多设备状态。
  • 画面标签：开启摄像头或门锁的 MJPEG 推流，实时观看画面；锁画面可上传人脸照片作为登记住户。
  • 报文标签：查看所有 WebSocket 收发报文，用于协议教学与调试。

3.4 人脸开锁与登记

当锁画面来源为摄像头/视频流并开启推送时，网关会对每帧做人脸检测：

  • 识别到已登记人脸 → 自动开锁，状态显示「识别通过 · 姓名」。
  • 识别到未登记人脸 → 连续确认后弹出横幅询问「是否登记用户」，可命名保存到 camera/faces/，重启仍有效。
旧版「模拟住户人脸 / 模拟访客」按钮已移除；人脸识别完全由上传画面或摄像头实时帧驱动。

4. WebSocket 接口

端点：ws://<host>:<port>/ws。建链后服务端主动推 hello、snapshot、event。 所有消息使用同一信封： 

{ "v": "1.0", "type": "command", "id": "ui-xxx", "ts": 1796000000000,
  "payload": { "deviceId": "light.living", "action": "set",
               "params": { "power": true, "brightness": 80 } } }

4.1 控制设备

设备类型actionparams
lighton / off / toggle / set{ power, brightness, colorTemp }
acon / off / toggle / set{ power, mode, targetTemp, fan }
cameraset / pan / nudge / arm{ power, streaming, armed } / { pan } / { delta } / { armed }
locklock / unlock可选 { person }

4.2 场景

{ "type": "scene", "payload": { "sceneId": "home" } }

可用场景：home（回家）、away（离家）、sleep（睡眠）、movie（观影）。

4.3 关键消息类型

方向type作用
S→Csnapshot全量设备影子、场景、站点、天气、最近事件
S→Cstate单设备增量更新，所有客户端广播
S→Cevent日志与安防事件
S→Cack命令回执，ref 关联请求 id
S→Cvideo流信令（通道、推流状态、云台、识别结果）
S→CfaceEnroll陌生脸登记询问
C→Scommand / scene / snapshot / setup / ping控制、切场景、拉全量、写位置、心跳

4.4 视频流

像素不走 WebSocket，直接通过 HTTP 长连接拉 MJPEG： 

<img src="http://localhost:8080/?stream=233666" />

通道分配：客厅摄像头 233666，大门人脸锁 233667。 先用 command 发 stream: { on: true } 开启推流，再打开 <img>。

5. MQTT 接口

项目内置 integrations/ha_bridge.py，它是一个零侵入的双向 MQTT 桥接器： 作为普通 WebSocket 客户端连网关，同时作为 MQTT 客户端连 broker。

5.1 启动桥接器

pip install paho-mqtt websockets
python integrations/ha_bridge.py --mqtt-host 127.0.0.1

5.2 状态主题

主题说明
mshouse/<deviceId>/state设备状态，retained
mshouse/gateway/state当前场景、在家状态、室外温湿度、地点名
mshouse/event事件流（安防告警、场景切换）
mshouse/bridge/status桥接器在线状态（LWT 遗嘱）

5.3 命令主题

主题负载示例
mshouse/light.living/set{"state":"ON","brightness":80} 或 OFF
mshouse/lock.entry/setLOCK / UNLOCK
mshouse/ac.living/power/setON / OFF
mshouse/ac.living/mode/setcool / heat / fan_only / dry / auto
mshouse/ac.living/temp/set25
mshouse/ac.living/fan/setlow / medium / high / auto
mshouse/camera.living/stream/setON / OFF
mshouse/camera.living/pan/set180
mshouse/scene/home/setPRESS
注意枚举翻译：网关内部风速用 mid，MQTT 侧需用 medium；空调模式网关用 fan，MQTT 侧需用 fan_only。桥接器会自动翻译，直接发送 HA 风格值即可。

6. 应用与生态

6.1 接入 Home Assistant

桥接器启动后会向 homeassistant/<component>/<object_id>/config 发布自动发现配置， HA 里只要添加 MQTT 集成，实体就会自动出现，无需写 YAML。 摄像头画面需额外在 configuration.yaml 配一个 mjpeg 平台（MQTT Discovery 不支持 camera 实体）。

6.2 二次开发 / 自己写客户端

  • 参考 public/demo.html：单文件、零依赖、完整展示了协议收发。
  • 参考 scripts/selfcheck.py：Python 版协议自检，展示了如何等待 ack、断言状态。
  • 参考 integrations/ha_bridge.py：如何把网关协议翻译成 MQTT。

6.3 与真实硬件结合

把门锁画面来源改成 RTSP 摄像头，或把门厅画面改成真实门口摄像头，即可用真实人脸开门； 把客厅摄像头画面来源改成真实摄像头，即可在三维沙盘中看到真实房间画面。 服务端做来源切换，客户端一行代码不用改。

6.4 教学用途

  • 协议课：用报文面板展示 WebSocket 全双工、ack/state 分离、广播与回执。
  • 物联网课：用 MQTT 桥接器展示私有协议 → 标准协议的转换、retained 状态、LWT 可用性。
  • 数字孪生课：用三维沙盘展示 CPS 映射——点击虚拟设备控制真实（或虚拟）物理状态。
  • 自动化课：在 HA 里写自动化，用这栋虚拟别墅验证规则，再迁移到真实设备。
