1. 概述

MSHouse 是一套纯软件运行的虚拟智能家居，用数字孪生的方式还原一栋两层别墅： 客厅、厨房、主卧、卫生间、门厅五个房间，灯、空调、温湿度传感器、云台摄像头、人脸门锁、电动窗帘六类设备。 所有设备都有真实的状态、响应与联动逻辑，不依赖任何实体硬件，适合课堂教学、协议演示与二次开发。

系统分为两层：

  • 网关（server）：FastAPI + asyncio，维护设备影子、执行场景、广播状态、提供 MJPEG 画面流。
  • 呈现（public）：Three.js 三维沙盘 + 控制面板，与网关通过 WebSocket 通信。

核心设计是协议与呈现分离：只要理解 WebSocket/MQTT 报文，就能用任意语言或平台控制这栋房子。

3. 工作流程

3.1 启动

  1. 安装依赖：pip install -r requirements.txt
  2. 启动网关：python -m server.main（默认 http://localhost:8080）
  3. 浏览器打开首页，WebSocket 自动连接并拉取全量设备影子。

3.2 首次使用

点击顶部「设置」按钮，输入初始化口令后，设置页按用途分成三张卡片： 地点（地点名称 / 详细地址 / 经纬度）、摄像头（大门锁画面来源）、 人脸锁（人脸登记库的登记与删除）。

在「地点」里写入经纬度后，网关会按当地天气预报初始化室外温湿度，并影响室内传感器与空调的初始值。 在「摄像头」里可把大门锁画面来源切换为：静态画面（默认，按天气切换）、本机摄像头、 网络视频流（RTSP / HTTP-MJPEG）、浏览器摄像头。

什么是「浏览器摄像头」：用打开这个网页的那台设备（笔记本 / 手机 / 平板） 的摄像头推流给网关。网关本身没有摄像头、或者摄像头在另一台机器上时用这个。 选中后点「开启摄像头」授权，再回「画面」标签点「推送画面」，画面就会出现在大门通道里， 同时被送去做人脸识别。注意它只在网页开着的时候才有画面， 而且浏览器只在 https 或 localhost 下才允许访问摄像头。
「人脸锁」卡片：登记库里列出全部已登记用户，并区分「内置登记照」与「现场登记」。 可以在这里直接上传照片登记新用户；如果浏览器摄像头正开着，还能点 「用摄像头抓拍登记」当场拍一张。每行右侧的「删除」会把人脸图连同特征一起删掉， 重启也不会复活。登记 / 删除都要带设置口令 —— HTTP 端点没有 WebSocket 那样的会话可挂鉴权， 口令由前端从刚验证过的输入框里带过去。
口令从哪来：口令不以明文出现在源码或网页里。 首次启动网关时，控制台会打印一个随机口令（只打印一次，请立即保存）； 也可以运行 python -m server.hash_password 自定义， 把输出的哈希填进 config.toml 的 security.setup_password_hash。 网关只存哈希，事后无法反推。
连接也需要令牌：WebSocket 建链时必须携带访问令牌（同样打印在启动日志里， 或写入 config.toml 的 security.token）。 顶部「设置」里填一次即可，之后记在浏览器本地。

3.3 日常交互

  • 三维视图：拖拽旋转、滚轮缩放、点击设备查看高亮。房子前方显示当前地点名称。
  • 控制面板：右侧「控制」标签分页列出所有设备卡片，可直接开关、调光、调温、转动云台、上锁/开锁、调整窗帘开度。
  • 场景按钮：顶栏「回家 / 离家 / 睡眠 / 观影」一键批量切换多设备状态（睡眠/离家自动关窗帘）。
  • 画面标签：开启摄像头或门锁的 MJPEG 推流，实时观看画面。 若大门锁画面来源是「浏览器摄像头」，这里还会多出一栏设备选择与 「开启浏览器摄像头」按钮。人脸登记在「设置 → 人脸锁」里做。
  • 报文标签：查看所有 WebSocket 收发报文，用于协议教学与调试。

3.4 人脸开锁与登记

当锁画面来源为摄像头 / 视频流 / 浏览器摄像头并开启推送时，网关会对实时画面做人脸识别 （YuNet 检测 + SFace 识别，OpenCV Zoo 的 INT8 块量化模型， 128 维特征 + 余弦距离，distance = 1 − cos ≤ 0.637 判定为本人）：

  • 识别到已登记人脸 → 自动开锁，状态显示「识别通过 · 姓名」。
  • 识别到未登记人脸 → 连续确认后弹出横幅询问「是否登记用户」，可命名保存到 camera/faces/，重启仍有效。
  • 已登记用户可在「设置 → 人脸锁」卡片里查看、登记与删除；登记后立刻生效，不用重启。
  • 内置登记照是 camera/face.jpg；没有它也能用，走「登记用户」现场注册即可。
旧版「模拟住户人脸 / 模拟访客」按钮已移除；人脸识别完全由上传画面或摄像头实时帧驱动。 阈值可在 config.toml 的 [streams.lock_entry.face] 里调， 运行状态（含实际加载的模型名）见 GET /health 的 lock.face。

4. WebSocket 接口

端点：ws://<host>:<port>/ws。需要访问令牌（通过子协议 bearer.<token>、查询串 ?token= 或首帧 hello 携带）。 建链并认证后服务端主动推 hello、snapshot、event。 所有消息使用同一信封： 

{ "v": "1.0.0", "type": "command", "id": "ui-xxx", "ts": 1796000000000,
  "payload": { "deviceId": "light.living", "action": "set",
               "params": { "power": true, "brightness": 80 } } }

控制命令走两阶段：网关先回 ack（status: "ACCEPTED"，表示已受理）， 设备真正执行后再广播 state（stateKind: "confirmed"）。 完整说明见仓库内的 docs/INTEGRATION.md。

4.1 控制设备

设备类型actionparams
lighton / off / toggle / set{ power, brightness, colorTemp }
acon / off / toggle / set{ power, mode, targetTemp, fan }
cameraset / pan / nudge / arm{ power, streaming, armed } / { pan } / { delta } / { armed }
curtainopen / close / toggle / set{ position }（0–100，100 为全开、0 为全闭）
locklock / unlock可选 { person }

4.2 场景

{ "type": "scene", "payload": { "sceneId": "home" } }

可用场景：home（回家）、away（离家）、sleep（睡眠）、movie（观影）。

4.3 关键消息类型

方向type作用
S→Chello握手（网关标识、协议版本、是否已认证）
S→Csnapshot全量设备影子、场景、站点、天气、最近事件
S→Cstate单设备更新，带 stateKind（delta / full / confirmed）与 seq
S→Cevent日志与安防事件
S→Cack命令回执，ref 关联请求 id，错误为结构化 errorInfo
S→Cvideo流信令（通道、推流状态、云台、识别结果）
S→Cfault设备故障上报（灯珠损坏、滤网脏堵…）
S→Cota固件升级进度（下载 / 校验 / 安装 / 重启 / 生效）
S→CfaceEnroll陌生脸登记询问
S→Cping服务端心跳，客户端须回 pong
C→Scommand / scene / snapshot / setup / ping控制、切场景、拉全量、写位置、心跳
C→Sresync序号跳号后请求全量对齐
C→Sota发起固件升级

4.4 视频流

像素不走 WebSocket，直接通过 HTTP 长连接拉 MJPEG： 

<img src="http://localhost:8080/?stream=233666" />

通道分配：客厅摄像头 233666，大门人脸锁 233667。 先用 command 发 stream: { on: true } 开启推流，再打开 <img>。

客厅画面里画着入户门：门锁 unlock 后门扇会向室内转开，门洞透出室外光线； 左下角常驻 DOOR OPEN / DOOR LOCKED 状态牌，云台转到任何角度都能判断门是否开着。

5. MQTT 接口

项目内置 integrations/ha_bridge.py，它是一个零侵入的双向 MQTT 桥接器： 作为普通 WebSocket 客户端连网关，同时作为 MQTT 客户端连 broker。

5.1 启动桥接器

pip install paho-mqtt websockets
python integrations/ha_bridge.py --mqtt-host 127.0.0.1

5.2 状态主题

主题说明
mshouse/<deviceId>/state设备状态，retained
mshouse/gateway/state当前场景、在家状态、室外温湿度、地点名
mshouse/event事件流（安防告警、场景切换）
mshouse/bridge/status桥接器在线状态（LWT 遗嘱）

5.3 命令主题

主题负载示例
mshouse/light.living/set{"state":"ON","brightness":80} 或 OFF
mshouse/lock.entry/setLOCK / UNLOCK
mshouse/ac.living/power/setON / OFF
mshouse/ac.living/mode/setcool / heat / fan_only / dry / auto
mshouse/ac.living/temp/set25
mshouse/ac.living/fan/setlow / medium / high / auto
mshouse/camera.living/stream/setON / OFF
mshouse/camera.living/pan/set180
mshouse/scene/home/setPRESS
注意枚举翻译：网关内部风速用 mid，MQTT 侧需用 medium；空调模式网关用 fan，MQTT 侧需用 fan_only。桥接器会自动翻译，直接发送 HA 风格值即可。

6. 应用与生态

6.1 接入 Home Assistant

桥接器启动后会向 homeassistant/<component>/<object_id>/config 发布自动发现配置， HA 里只要添加 MQTT 集成，实体就会自动出现，无需写 YAML。 摄像头画面需额外在 configuration.yaml 配一个 mjpeg 平台（MQTT Discovery 不支持 camera 实体）。

6.2 二次开发 / 自己写客户端

  • 参考 public/demo.html：单文件、零依赖、完整展示了协议收发。
  • 参考 scripts/selfcheck.py：Python 版协议自检，展示了如何等待 ack、断言状态。
  • 参考 integrations/ha_bridge.py：如何把网关协议翻译成 MQTT。

6.3 与真实硬件结合

把门锁画面来源改成 RTSP 摄像头，或把门厅画面改成真实门口摄像头，即可用真实人脸开门； 把客厅摄像头画面来源改成真实摄像头，即可在三维沙盘中看到真实房间画面。 服务端做来源切换，客户端一行代码不用改。

网关没有摄像头也没关系：选「浏览器摄像头」，用手机或笔记本的摄像头就能演示真实人脸开锁 —— 画面由浏览器 getUserMedia 抓帧后 POST /api/lock/frame 推给网关， 走的仍然是「信令走 WebSocket、像素走 HTTP」这一套分工，只是方向反过来。

6.4 教学用途

  • 协议课：用报文面板展示 WebSocket 全双工、ack/state 分离、广播与回执。
  • 物联网课：用 MQTT 桥接器展示私有协议 → 标准协议的转换、retained 状态、LWT 可用性。
  • 数字孪生课：用三维沙盘展示 CPS 映射——点击虚拟设备控制真实（或虚拟）物理状态。
  • 自动化课：在 HA 里写自动化，用这栋虚拟别墅验证规则，再迁移到真实设备。
